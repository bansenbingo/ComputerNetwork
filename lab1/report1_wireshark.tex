\section{实验内容和原理}
\subsection{实验内容}
本实验以 Wireshark 4.6.8 为协议分析工具，在 Windows 环境中完成网络数据包的捕获和分析。实验主要包括：认识 Wireshark 界面；捕获网络接口上的全部数据包；使用显示过滤器和捕获过滤器筛选数据包；执行 Ping、ARP、Tracert、Nslookup、Netstat、Route、Net View、Telnet 等命令；观察这些操作在网络上产生的协议数据包，并对抓包结果进行分析。

\subsection{基本原理}
\begin{enumerate}
  \item \textbf{分层通信原理。}网络通信按照协议栈分层组织。以太网帧承载 IP 数据报，IP 数据报承载 TCP、UDP 或 ICMP 等传输层及网络层协议，应用层协议（如 DNS、HTTP）再通过 TCP 或 UDP 传输。Wireshark 可以将一个数据包按照协议层次展开，帮助分析各层首部字段及封装关系。
  \item \textbf{ARP 原理。}在 IPv4 局域网中，主机发送数据前需要根据目标 IPv4 地址获得下一跳设备的 MAC 地址。发送方广播 ARP Request，目标主机返回 ARP Reply，并将结果写入 ARP 缓存。因此，清空 ARP 缓存后访问局域网网关时，通常可以观察到 ARP 请求和响应。
  \item \textbf{ICMP 原理。}Ping 使用 ICMP Echo Request 和 Echo Reply 测试可达性，并根据请求和响应的时间差估算往返时延。Tracert 则通过逐步增加 IP 首部中的 TTL，使沿途路由器返回 ICMP Time Exceeded 报文，从而推断到目标主机的路径。
  \item \textbf{DNS 原理。}DNS 将域名转换为 IP 地址。客户端通常通过 UDP 53 端口向 DNS 服务器发送查询，服务器返回 A、AAAA 等资源记录。执行 Nslookup 时，可以在 Wireshark 中观察 DNS Query 和 DNS Response。
  \item \textbf{TCP 原理。}TCP 是面向连接的可靠传输协议，通常通过 SYN、SYN/ACK、ACK 完成三次握手，连接结束时通过 FIN/ACK 进行有序释放。Telnet 连接本机 HTTP 服务时，Telnet 负责建立 TCP 连接，手工输入的 GET 请求属于 HTTP 应用层数据。
  \item \textbf{HTTP 原理。}HTTP 请求由请求行、请求头和空行组成。例如，\texttt{GET / HTTP/1.0} 表示请求服务器返回根目录资源。Python 的 \texttt{http.server} 返回 \texttt{200 OK} 和目录索引页面，随后关闭连接。
\end{enumerate}

\section{实验结果与分析}
\subsection{Wireshark 的两种过滤器有什么不同？}
\answer{捕获过滤器和显示过滤器的作用阶段不同。捕获过滤器在开始抓包前生效，按照过滤条件限制实际写入捕获文件的数据包；显示过滤器在抓包完成后生效，只改变数据包列表中当前显示的内容，不会删除原始捕获文件中的数据包。两者即使使用相似的概念，语法体系也不同。例如，捕获过滤器通常写为 \texttt{tcp port 80}，显示过滤器写为 \texttt{tcp.port == 80}。因此，若希望减少抓包文件大小、降低捕获开销，应使用捕获过滤器；若希望在已经完成的抓包中反复分析不同协议，应使用显示过滤器。}

\subsection{哪些网络命令会在 Wireshark 中产生数据包，为什么？}
\answer{\texttt{ping} 会产生 ICMP Echo Request/Reply；\texttt{tracert} 会通过递增 TTL 产生 ICMP 超时报文或回显响应；\texttt{nslookup} 会向 DNS 服务器发送 DNS 查询；\texttt{telnet} 会建立 TCP 连接，并在连接中传输手工输入的 HTTP 数据；\texttt{net view} 或建立网络共享映射时，可能产生 DNS、NetBIOS、SMB/SMB2 和 TCP 数据包。\texttt{ipconfig /all}、\texttt{arp -a}、\texttt{netstat -ano} 和 \texttt{route print} 主要读取本机已有的配置或状态表，通常不会因为查询动作本身产生新的网络数据包；\texttt{route add} 主要修改本机路由表，也不会自动产生业务数据包。实际抓包结果还可能受到 DNS 缓存、ARP 缓存、后台服务、网络发现和防火墙策略影响。}

\subsection{Ping 一个域名和 Ping 一个 IP 地址有什么不同？}
\answer{Ping IP 地址时，程序可以直接向目标 IPv4 地址发送 ICMP Echo Request；若目标不在本地网络，还需要通过 ARP 获取默认网关的 MAC 地址。Ping 域名时，通常先进行 DNS 解析，将域名转换成 IPv4 或 IPv6 地址，再发送 ICMP 报文。因此，抓包时 Ping 域名可能先出现 DNS Query/Response，而 Ping IP 地址通常没有这一步。不过，如果系统已有 DNS 缓存，或者目标使用 IPv6、禁止 ICMP，实际现象可能与理论过程有所差异。}

\section{实验结论}
本实验完成了 Wireshark 4.6.8 的基本操作以及 Windows 常见网络命令的联合使用。通过完整捕获、显示过滤和捕获过滤，掌握了从“捕获全部流量”到“按协议定位数据包”的基本分析流程。实验观察表明，命令行操作并不是孤立的工具调用，而是会在协议栈中表现为不同的网络行为：Ping 对应 ICMP，Nslookup 对应 DNS，Telnet 连接 HTTP 服务则对应 TCP 建连和 HTTP 应用数据。ARP、DNS 和 TCP 握手分别体现了地址解析、域名解析和可靠传输建立过程。

本实验还验证了本机回环通信的抓包特点：访问 \texttt{127.0.0.1:8765} 时应选择 Npcap Loopback Adapter，而不是普通 Wi-Fi 或 Ethernet 接口。Telnet 手工发送 HTTP 请求后，服务器返回目录索引页面，说明 TCP 连接、HTTP 请求和响应过程均正常完成。总体而言，Wireshark 能够把抽象的网络命令转化为可观察、可解释的数据包，为理解计算机网络协议提供了直观手段。

\section{讨论与心得}
实验过程中遇到的主要问题是 Telnet 连接本机 HTTP 服务时，最初使用 8000 端口出现连接卡住或连接重置现象。通过 \texttt{netstat -ano} 和 \texttt{Test-NetConnection} 检查端口监听状态后，将服务改为绑定 \texttt{127.0.0.1:8765}，并验证端口处于 LISTENING 状态，最终成功完成 Telnet 连接和 HTTP 请求。这个过程说明，遇到网络实验问题时，不能只根据应用程序表面的提示判断，而应依次检查服务是否启动、端口是否监听、地址是否匹配、接口是否选择正确以及协议请求是否完整。

通过本实验，我进一步理解了捕获过滤器与显示过滤器的区别，也认识到同一个命令在不同缓存和网络环境下可能产生不同的数据包。例如，ARP 或 DNS 缓存存在时，某些预期的数据包可能不会再次出现；而访问共享资源时，网络发现和防火墙设置也会影响实验结果。今后进行抓包实验时，应先明确实验目标，再选择正确的接口、过滤器和触发命令，同时保存原始 pcapng 文件，避免只依赖截图进行分析。

本实验的改进建议是：每个命令最好单独进行一次“开始抓包—执行命令—停止抓包”的操作，并统一记录命令、接口、过滤器、抓包文件和截图名称；对于 ARP、DNS 等具有缓存影响的协议，可在实验前清理缓存或更换查询对象；对于 Telnet/HTTP 实验，应优先使用本机可控的 Python HTTP 服务，以降低外部网络不可达、HTTPS 加密和服务器策略造成的不确定性。
