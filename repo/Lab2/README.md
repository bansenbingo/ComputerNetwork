# Lab2 Socket 实验使用说明

本目录包含基于 Windows Winsock 的 TCP 客户端/服务端程序。服务端负责接收连接、处理请求和转发消息；用户端负责显示交互菜单、发送请求并接收服务端响应。

## 文件说明

| 文件 | 作用 |
|---|---|
| `server.cpp` | 服务端源代码，接收并发客户端连接，每个客户端由独立工作线程处理 |
| `server.exe` | 已编译的服务端程序 |
| `user.cpp` | 用户端（客户端）源代码，包含交互菜单、接收线程和线程安全消息队列 |
| `user.exe` | 已编译的用户端程序 |
| `lab2-socket-experiment-requirements.md` | 实验要求、协议设计和验收检查清单 |

程序使用底层 Winsock Socket API，包括 `socket`、`bind`、`listen`、`accept`、`connect`、`send` 和 `recv`，传输层协议为 TCP。服务端和用户端都采用多线程，并通过 `sendAll`、`recvExact` 处理 TCP 的分片、合并和部分发送问题。

## 运行环境

- Windows
- MinGW g++（支持 C++17）
- Winsock2（Windows 系统自带）
- 编译时必须链接 `ws2_32` 库

## 编译

在本目录打开 PowerShell 或命令提示符，执行：

```powershell
g++ -std=c++17 -Wall -Wextra -pedantic server.cpp -o server.exe -lws2_32
g++ -std=c++17 -Wall -Wextra -pedantic user.cpp -o user.exe -lws2_32
```

重新编译后，再运行新生成的 `.exe` 文件。

## 服务端使用方法（接收端）

1. 双击 `server.exe`，或在终端执行：

   ```powershell
   .\server.exe
   ```

2. 服务端自动使用学号后四位 `4669` 作为 TCP 监听端口，不需要输入端口。
3. 看到 `Listening on TCP port 4669` 后，服务端已经可以接受用户端连接。
4. 服务端会输出客户端编号、客户端 IP/端口、请求类型、消息转发和断开连接等日志。
5. 按 `Ctrl+C` 停止服务端。服务端会关闭监听 Socket，并清理已连接客户端和工作线程。

服务端绑定 `0.0.0.0:4669`，因此既可以接受本机连接，也可以接受局域网中其他计算机的连接。

## 用户端使用方法（输入端）

1. 服务端启动后，在另一个终端执行：

   ```powershell
   .\user.exe
   ```

2. 菜单包含以下 7 个选项：

   | 选项 | 功能 |
   |---|---|
   | `1. Connect` | 输入服务器 IP 或主机名并连接。端口自动使用 `4669`，连接成功后启动接收线程 |
   | `2. Disconnect` | 关闭当前 TCP 连接并停止接收线程 |
   | `3. Get server time` | 请求并显示服务端当前时间 |
   | `4. Get server name` | 请求并显示服务端计算机名 |
   | `5. List active clients` | 获取并显示当前活动客户端的编号、IP 和端口 |
   | `6. Send message` | 输入目标客户端编号和消息，请求服务端转发 |
   | `7. Exit` | 已连接时先断开，再退出程序；未连接时直接退出 |

3. 未连接时只能选择 `1` 或 `7`。
4. 使用选项 `6` 发送消息前，必须先使用选项 `5` 获取活动客户端列表。发送时输入列表中的目标客户端编号，再输入消息内容。
5. 用户端接收线程持续调用 `recv`，将响应和被转发消息放入线程安全队列；主线程负责从队列取出并显示，因此等待用户输入时也能及时显示收到的转发消息。

## 推荐测试流程

### 本机测试

1. 打开终端 A，运行 `server.exe`。
2. 打开终端 B，运行 `user.exe`，选择 `1`，服务器地址输入 `127.0.0.1`。
3. 打开终端 C，再运行一个 `user.exe`，同样连接 `127.0.0.1`。
4. 在任意用户端选择 `5`，记录另一个用户端的编号。
5. 选择 `6`，输入目标编号和消息，确认另一个用户端显示发送者编号、IP、端口和消息内容。
6. 分别测试获取时间、获取服务端名称、主动断开和退出。
7. 可让两个用户端同时发送请求，以验证服务端的并发处理能力。

### 局域网测试

1. 在运行 `server.exe` 的计算机上查看局域网 IPv4 地址，例如 `192.168.1.20`。
2. 在另一台计算机运行 `user.exe`，选项 `1` 中输入该局域网地址；端口仍然是 `4669`。
3. 若连接失败，在 Windows 防火墙入站规则中允许 TCP `4669`，并确认两台计算机处于可互通的同一网络。

## 常见问题

- **`bind/listen failed`**：端口 `4669` 已被其他程序占用，或程序没有权限绑定端口。关闭占用端口的程序后重试。
- **`connect failed`**：服务端未启动、服务器地址错误、Windows 防火墙拦截，或客户端与服务器网络不通。
- **显示只能选择 Connect 和 Exit**：用户端尚未连接服务端，先选择 `1`。
- **发送消息被拒绝**：必须先选择 `5` 获取活动客户端列表；目标编号必须来自该列表，且不能填写自己的编号。
- **修改源代码后行为没有变化**：需要重新执行编译命令，再运行新生成的 `server.exe` 或 `user.exe`。
- **服务端停止后客户端异常断开**：这是预期行为；客户端接收线程会检测连接关闭并回到未连接状态。

## 与实验要求的对应关系

- 使用 TCP 和底层 C Socket API，不使用 Socket 封装类。
- 服务端监听端口为学号后四位 `4669`。
- 服务端通过 `accept` 接收多个客户端，并为每个连接创建工作线程。
- 用户端包含要求的 7 个菜单选项，并在连接成功后创建接收线程和消息队列。
- 服务端支持时间、计算机名、活动客户端列表和客户端间消息转发。
- 自定义报文头使用 `type`、`request_id`、`body_length` 三个网络字节序字段；主动转发消息使用独立的消息类型。
